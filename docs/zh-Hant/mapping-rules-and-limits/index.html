章節索引要穩定，不必要求翻譯後的標題同字

解讀報告前，先了解空標題、重複標題、前言與有限的 Markdown 語法範圍。

工具用遇見章節的順序作為識別，不用標題 slug。這樣不會假裝不同語言的標題必須同字，也能清楚區分重複標題。

索引規則

支援的 ATX 標題依序取得 1、2、3 等索引，包括巢狀標題。空標題 # 仍有獨立索引，在 Markdown 報告中顯示為「(untitled)」。兩個「Notes」是不同章節。第一個標題之前若有非空內容，屬於索引 0；空白文件沒有章節。預設模式只將前言 0 與另一份文件的前言 0 配對，其餘標題按出現順序配對。

#
# Notes
# Notes

索引：1、2、3
明確映射：[[1, 1], [3, 2]]

明確映射模式只處理列出的配對；未列出的章節，包括前言，都保持未配對。重複索引或不存在的索引會報錯，不會猜測。插入新標題後，應重新查看章節清單並調整映射。

實際計數的內容

支援子集包括最多三個前導空格的 ATX 標題、反引號或波浪號程式碼圍欄、獨立行 $$ 區塊，以及簡單的行內圖片與連結目標。程式碼與公式內部不會產生標題。程式語言、圖片目標和連結目標按多重集合比對：重複次數重要，順序不重要。每個標題都開始新章節；子標題下的物件歸該子節，不向上重複累計。

刻意不解析的語法

這不是完整 CommonMark 解析器。Setext 標題、參照式連結、目的網址內的巢狀括號、原始 HTML、行內公式、表格與複雜巢狀語法不在範圍內。未閉合的程式碼或公式區塊也不做語法 lint。依賴報告之前，應先正規化這些寫法或人工檢查。

網址變更可能是合理的本地化；區塊數量相同也可能隱藏語意遺漏。輸出只能協助決定先閱讀哪一段，不可用於翻譯品質評分或完整性認證。

來源為 PDF 時，相關的 KolmoPDF 轉換工作流可透過會上傳文件的獨立雲端服務提供上游 Markdown。轉換與本工具的有限結構對照處理不同問題；區塊數量相同，仍不能當作翻譯品質結論。
